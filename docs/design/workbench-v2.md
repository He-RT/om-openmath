## 1. 保留的用户决定

以下是用户明确作出的决定，本设计不改：

- 右栏助手：上方对话独立滚动，下方固定输入框；模型选择在输入框内；可粘贴、拖入任意文件（2026-10-08，[agent-composer.md](agent-composer.md)）。
- 只列出已配置的供应商模型，不硬编码，不导入旧配置（2026-10-09）。
- 保留 OpenMath 绿色强调色，Apple 原生组件优先，参考 Telegram 的输入、状态与动效机制（2026-10-08，[macos-ux.md](macos-ux.md)）。
- Mac 首版目标 Apple Silicon、macOS 27+；普通 `.omnb` v1 兼容；不迁移旧数据（[macos-installation.md](macos-installation.md)）。
- 优先交付 Mac 和 Web，性能门槛不降：原 53 条 CLI < 200 ms，Mac 与 Web 整次 < 1 s，10 KiB 输入到绘制 p95 ≤ 50 ms（2026-10-15）。
- 不改系统输入法、安全和权限设置（2026-10-12）。

## 2. 产品、用户与主要任务

OpenMath 是以精确求解为核心的数学笔记本：用户写数学源码，Rust 内核给出精确、可验证的结果、步骤和图形；助手可以读取、修改、运行笔记本，所有修改可撤销。

主要用户：学生、工程师、科研人员，以中文为主，熟悉 Mathematica、Jupyter 或 LaTeX 中的一种。

三个主要任务：

1. **写数学，读可信结果。** 一眼看出结果是否精确、是否已验证、是否有条件、是否已过期。
2. **看懂图形和推导。** 图形可直接操作，推导步骤可展开。
3. **把多步工作交给助手，并且看得见它做了什么。** 每次读取、修改、运行都能定位和撤销；结束时只陈述实际发生的事。

## 3. 设计原则

1. **输入和结果是两种材质。** 用户输入放在浅灰“源码槽”里（等宽字体）；内核结果直接排在纸面上（数学字体）。不用卡片包住每个单元格。
2. **左轨说明结果状态。** 每个数学单元格左侧有一条 3 pt 竖轨，颜色和线型表示已验证、有条件、过期、运行中、出错。轨道顶端的靛蓝短段表示“最近一次由助手修改”。轨道从不单独表达信息，旁边总有文字状态。
3. **助手把操作摆出来。** 回复中的每一步操作是一行：动词、对象、状态，可以定位、看差异、撤销。结束时只陈述宿主核实的事实。
4. **原生优先。** Mac 用系统窗口、侧栏、工具栏、菜单、表单和 SF Symbols；Web 遵循同一结构，用标准 HTML 控件。只有数学单元格、左轨、图形和操作记录是自绘。
5. **需要时才出现。** 单元格的运行和更多按钮在悬停或选中时出现；图形信息、完整原结果、技术字段放在展开项或检查器里。

## 4. 视觉系统

### 4.1 颜色

令牌名在 Mac 上对应资产目录颜色（带深色变体），在 Web 上对应 CSS 变量。Mac 能用系统语义色的地方直接用系统色，表中“Mac 映射”一列给出对应关系。

| chrome | `#F3F4F3` | `#26282A` | 检查器、工具区 | `windowBackgroundColor` |
| sidebar | `rgba(239,241,240,.92)` | `rgba(42,44,46,.9)` | 目录侧栏 | 系统侧栏材质（自动） |
| well | `#F4F5F4` | `#2A2C2F` | 源码槽、代码块之外的输入区 | 资产色 `Well` |
| line / line-strong | `#E2E5E3` / `#CDD2CF` | `#36393B` / `#4A4E50` | 分隔线、边框 | `separatorColor` / 资产色 |

| plot-1 / plot-2 | `#2F6BD8` / `#C8641B` | `#7AA7F5` / `#F0A060` | 图形序列（不用绿色和靛蓝，避免和状态混淆） | 资产色 |

已验证对比度（WCAG）：浅色纸面上 ink 16.8、ink-2 6.1、green 5.7、indigo 6.1、amber 5.4、red 5.3；深色纸面上全部 ≥ 6.2。ink-3 在浅色约 3.7，只用于占位文字和装饰性次要信息。白字配绿色按钮 5.7；深色模式绿色按钮配深色字 8.6。

用色规则：

- 绿色只表示品牌、“已验证/成功”和主操作（运行、发送）。图形曲线不用绿色。
- 靛蓝只表示“助手”：回复署名、操作记录的竖线、单元格左轨顶端的修改标记、目录里的环形标记。用户看到靛蓝就知道“这是助手做的”。
- 状态从不只靠颜色：每个状态都有图标和文字（第 5.2 节）。

### 4.2 字体：三种声音

| 声音 | 用途 | Mac | Web | 字号 / 行高 |
|---|---|---|---|---|
| 工具 | 界面、按钮、助手对话、标签 | SF Pro（系统字体） | `-apple-system, "PingFang SC", "Segoe UI", system-ui` | Mac 13/18；Web 14/21；对话 13.5/22 |
| 源码 | 数学源码、代码块、变量名 | SF Mono | `ui-monospace, "SF Mono", Menlo, Consolas` | 13.5/21.6 |
| 纸面 | 笔记本标题、文字单元格正文与标题 | New York（`.serif` 设计），中文回退宋体 | `"New York", ui-serif, "STIX Two Text"`（随包），中文回退 `"Songti SC", "Noto Serif SC"` | 标题 30/36 半粗；H2 21/27；正文 16.5/27.7 |
| 数学 | 结果、行内公式 | SwiftMath Latin Modern（已随包） | KaTeX（已随包） | 结果 ≈ 20 pt；行内跟随正文 |

理由：数学论文用衬线排版，笔记本的“纸面”跟着用衬线，和界面的无衬线拉开层次。New York 是 macOS 自带衬线，Mac 不需要额外字体。Web 随包 STIX Two Text（OFL 许可），不依赖在线字体服务。

### 4.3 间距、圆角、阴影

- 间距序列：4、8、12、16、20、24、32。单元格间距 26；纸面左右 48–56，手机 16。
- 圆角按层级区分，不统一：源码槽 8、代码块 6、用户气泡 14、输入框 14、菜单 11、芯片全圆、窗口和侧栏由系统决定（Mac 26+ 浮动侧栏约 12）。
- 阴影只用于浮层（菜单、弹出框、手机底部面板）。单元格、结果、操作记录都没有阴影。

### 5.2 数学单元格结构

```text
┃  ┌─────────────────────────────────────────────── ▶ ⋯ ┐   ← 源码槽（well），悬停或选中时出现运行和更多
┃  │ solve(x^2 - 5x + 6 = 0, x)                          │
┃  └─────────────────────────────────────────────────────┘
┃     x = 2,     x = 3                                       ← 结果，数学字体，过长横向滚动
┃     ✓ 精确解，已代入验证   2 个解  9 ms      步骤 绘图 复制⌄  ← 状态行：状态 · 摘要 · 用时 · 动作（右对齐）
↑ 左轨 3 pt
```

- 源码槽：圆角 8，内边距 10/14，右侧留 76 给工具按钮。当前单元格加一圈 1 pt 描边，不加阴影。
- 结果：与源码槽内容左对齐（缩进 14）。不再给每个解单独一大块；解集写成一行，超过 4 个解改用表格（序号、精确值、近似值）。
- 状态行：12 pt 次要色。动作是纯文字按钮，悬停才有底色。

左轨状态表：

| 状态 | 左轨 | 目录圆点 | 结果显示 | 状态文字（示例） | 读屏 |
|---|---|---|---|---|---|
| 未运行 | 1 pt 细灰线 | 空心灰 | 无结果；“尚未运行” | 尚未运行 | “未运行” |
| 运行中 | 绿色虚线向下流动（减少动态效果时为静态虚线） | 绿色 | 旧结果半透明 | 正在计算… 停止 | “正在计算” |
| 已验证 | 绿色实线 | 绿色 | 正常 | ✓ 精确解，已代入验证 | “已验证” |
| 精确但未验证 / 数值 | 绿色实线 | 绿色 | 正常 | ✓ 精确值 / ≈ 数值近似，20 位 | “精确” / “近似值” |
| 有条件成立 | 琥珀实线 | 琥珀 | 正常 + 条件芯片 | ⓘ 成立条件 k ≠ 0　有条件成立 | “有条件成立，条件 k 不等于 0” |
| 过期 | 灰色虚线 | 灰色空心 | 旧结果 42% 不透明 | 上次结果对应 a = 2，a 已改变　运行以更新 | “结果过期” |
| 出错 | 红色实线 | 红色 | 诊断框；有上次有效结果时也保留并标“上次结果” | ⚠ 1:11 表达式尚未完成，等号右侧需要表达式　定位 | “计算出错” |
| 未求值 | 灰色实线 | 灰色 | 原式 | 内核没有化简这个表达式（原样保留） | “未求值” |
| 助手修改 | 在上述状态之上，轨道顶端 18 pt 靛蓝 | 圆点外加靛蓝环 | 状态行多一个“助手新增 / 助手修改，查看对话” | — | 追加“由助手修改” |

“过期”的来源：源码被编辑，或它依赖的定义被改动（依赖信息来自内核）。过期提示写清原因，例如“上次结果对应 a = 2，a 已改变”。

### 5.3 结果类型

| 内核结果 | 显示 | 状态行动作 |
|---|---|---|
| 表达式 / 数值 | 数学排版一行，长式横向滚动 | 复制⌄（源码 / LaTeX / 数值） |
| 解集 | `x = 2, x = 3` 一行；> 4 个解用表格；重根标重数 | 步骤 · 绘图 · 复制⌄ |
| 有条件的解 | 同上，下面加琥珀条件芯片 | 步骤 · 复制⌄ |
| Root / 无法给出根式 | `Root(...)` 原式 + “≈ 1.1673…” | 数值精度⌄ · 复制⌄ |
| 无解 / 全体实数 / 区间 | 一句话加数学排版（∅、ℝ、区间） | 步骤 |
| 矩阵 ≤ 8×8 | 数学排版矩阵 | 复制⌄ · 导出⌄ |
| 大矩阵 / 表格 / 记录 | 原生表格（Mac `Table` / NSTableView；Web `<table>`），分页 | 导出 CSV/JSON |
| 二维图 | 画布占满结果宽度，高 250；图例在下方；缩放、复位浮在右上，悬停出现 | 图形信息 · 导出⌄（SVG/PNG/CSV） |
| 三维场景 | 画布高约 400，拖动旋转、滚动缩放；复位和全屏浮在右上 | 图形信息 · 导出⌄（OBJ/PNG） |
| 错误 | 红色诊断框：位置（行:列，等宽）+ 一句说明 + “定位” | 定位；有快速修复时加“修复” |
| 未求值 | 原式，灰色说明 | — |

“图形信息”展开后显示采样点数、三角形数、坐标范围、限制说明（例如“有限机器采样，不是认证的曲面边界”）。这些信息不放在默认视图里。

### 5.4 运行、停止与过期

- 运行中：保留旧结果（半透明），左轨流动，工具栏副标题写“正在运行单元格 5”，工具栏“运行”变“停止”。
- 接收新结果后直接替换，不做弹跳动画。
- 编辑源码立刻把结果标为过期；迟到的旧回复不能覆盖新源码对应的状态（沿用 [macos-host-state.md](macos-host-state.md) 的代次规则）。
- 停止：显示“正在停止”，确认后在单元格写“已停止”，保留已提交的前缀结果。

### 5.5 文字单元格

- **默认阅读态**：Markdown 渲染，正文用纸面字体，最大行宽 64 字符。行内 `$…$` 用数学字体排版。
- 双击或按“编辑”进入编辑态：显示 Markdown 源码（等宽，源码槽背景）。Esc 或 ⌘↩ 回到阅读态。
- 新建的文字单元格直接进入编辑态。
- 目录用文字单元格的 H1/H2 作分组标题（草案中的“求解”“图形”）。

### 5.6 代码块（文字单元格与助手回复通用）

参考 Telegram macOS（TelegramSwift `TextView.swift` 的 `TextViewBlockQuote(isCode:)` 和 `ChatMessageItem.swift` 的代码块头部）：**整个代码块是一个容器**，不是给每一行涂底色。

```text
▌ OpenMath                              复制   插入为单元格
▌ color: fn(p,u,v) => [0.06, 0.34 + 0.14*cos(12*u + …), 0.1]   ← 不换行，横向滚动
```

- 圆角 6，背景 `code-bg`，左侧 3 pt 竖条（OpenMath 代码用绿色，其他语言用 ink-3）。
- 头部一行：语言名（半粗 11.5）、复制、插入为单元格（仅 OpenMath 代码且为用户主动点击；插入后不自动运行）。
- 内容：等宽 12.5，`white-space: pre`，超出宽度横向滚动（Mac 用独立的水平 `NSScrollView`）。
- 行内代码：等宽 + 浅底，圆角 4，不加竖条。

### 5.7 插入、移动、删除

- 工具栏 `＋⌄`、单元格之间的“＋ 数学 / ＋ 文字”、⌥↩（运行并在下方插入）。默认插在当前单元格之后。
- 移动：更多菜单“上移/下移”和 ⌥⌘↑/↓；拖动只用左侧把手，不从文本选区起拖。
- 删除通过可撤销事务完成；删除后显示“已删除单元格 4　撤销”的提示，5 秒后消失（撤销始终可用 ⌘Z）。

### 5.8 空笔记本与首次启动

- 新笔记本：衬线标题占位“未命名笔记本”，一个已聚焦的数学单元格，占位文字“输入表达式，⌘↩ 运行”。
- 下面一行“从例子开始”：二次方程、函数图像、三维西瓜、地月 L2（来自 `docs/examples/`）。
- 没有配置模型时，助手显示一句说明和“添加模型”按钮；数学功能完全可用。

## 6. 检查器

右栏顶部为分段控件：**助手 · 步骤 · 变量**。切换时各自保留滚动位置和状态。文稿信息（文件位置、保存状态、版本）放在标题的弹出菜单里（Mac 原生文稿标题菜单），不占检查器。

**步骤。** 标题写“单元格 2 的推导步骤”和源码。每一步：序号、规则名（半粗）、数学式、可选一句说明。子步骤缩进，可折叠。数据只来自内核记录的步骤，没有记录时写“这个结果没有记录步骤”。

**变量。** 表格三列：名称（等宽）、值摘要、来自哪个单元格。点按一行定位到单元格。过期定义灰色并注明“已过期”；出错的写“未定义，单元格出错”。数据来自内核当前接纳的定义（Web 已有 `get_variables`；Mac 需要新增只读查询，见计划 C9）。

### 7.2 消息

- 用户消息：右对齐气泡，最大宽 88%。附件缩略图在气泡上方；单元格引用以“［单元格 8］”写在正文前。
- 助手回复：通栏，不加气泡。署名行“助手”（靛蓝）+ 模型名 + 模式。正文是 Markdown：行内数学、代码块（第 5.6 节）、表格都按笔记本同一规则渲染。回复里的代码不会自动执行。
- 流式输出：按约 75 ms 合批追加，已稳定的块不重排；没有逐字打字效果。
- 滚动：用户在底部时跟随新内容；向上翻阅时不抢滚动，底部出现“新消息 ⌄”小药丸。

### 7.3 操作记录

每条助手回复带自己的操作记录，按发生顺序穿插在回复正文之间（模型说一段话、做几步、再说一段话）。

数据模型（取代现在的 `trace: [String]`）：

```text
AgentAction {
  id, turn_id, call_id
  tool          // read_notebook / preview_source / apply_notebook_patch / run_cells / inspect_result / …
  verb          // 中文动词，由 tool 决定（见下表）
  object        // 由参数和结果生成：“新增单元格 8”“单元格 3、4”“三维场景，6,782 个三角形”
  status        // running / ok / failed / cancelled / unknown
  cells: [cell_id]
  transaction_ref?   // 修改类操作，用于差异和撤销
  error?        // 失败原因（工具返回的错误码和一句说明）
}
```

工具与显示：

| 工具 | 动词 | 对象示例 | 附加动作 |
|---|---|---|---|
| read_notebook | 读取笔记本 | 7 个单元格 / 单元格 3 | — |
| search_functions / get_function_docs | 查阅函数 | parametric_plot、scene | — |
| preview_source | 预览修改 | 新增 1 个数学单元格，无诊断 | 查看差异 |
| apply_notebook_patch | 修改笔记本 | 新增单元格 8 / 单元格 3 改 2 处 | 定位 · 查看差异 · 撤销 |
| run_cells | 运行 | 单元格 8，0.8 秒 / 单元格 3–5，1 个出错 | 定位 |
| inspect_result | 检查结果 | 解 x = 2, x = 3 / 三维场景，6,782 个三角形 | 定位 |
| evaluate_scratch | 临时计算 | 条纹频率 20 的颜色函数 | — |
| undo_transaction | 撤销修改 | 单元格 8 | — |
| get_operation_status | 核对操作 | 修改单元格 8：已提交 | — |

显示规则：

- 连续 3 个以上的读取类操作合并成一行（“读取笔记本和 2 个函数说明”）。
- 失败的操作**不隐藏**：红色 ✕ + 原因 + 下一步（“按错误信息补齐后重试”）。
- 操作超过 6 个时默认折叠为摘要行“N 个操作：修改 x 处，运行 y 次……”，点按展开。运行中的回复始终展开。
- “定位”滚动到单元格并用靛蓝闪一下边框；“查看差异”在行下展开源码差异（+/−，等宽）；“撤销”只撤销这一笔事务。

### 7.4 本轮结果与状态用语

回合结束时，在回复末尾显示“本轮结果”。**内容只来自宿主核实的事实**，不来自模型的自述：

| 行 | 数据来源 | 文字 |
|---|---|---|
| 修改 | 本回合提交的事务 | ✓ 新增 1 个单元格（单元格 8）/ 修改单元格 3 的 2 处 |
| 运行 | 本回合的运行回执 | ✓ 运行 1 个单元格，没有诊断 / ⚠ 运行 2 个单元格，单元格 5 出错 |
| 产出 | 本回合 inspect_result 和结果库 | ✓ 三维场景已生成，6,782 个三角形 / ✓ 解 x = 2, x = 3 已验证 |
| 未覆盖 | 被修改但没有重新运行的单元格 | ⚠ 单元格 8 修改后没有重新运行，结果过期 |
| 保存 | 文稿状态 | ◷ 尚未保存到文件（⌘S）/ ✓ 已保存 |

按钮：“撤销本轮修改”（把本回合所有事务作为一组撤销，一次 ⌘Z 等效）、“定位单元格 N”。
最后一行：结束方式 + 用时 + 模型请求次数。

结束方式只有四种，**不使用“已完成”**：

| 内部原因 | 显示 |
|---|---|
| 模型结束回合（`loop_stopped`） | 回合结束 |
| 用户停止 | 已停止，已完成的修改保留 |
| 出错（网络、供应商、配置） | 请求失败：〈原因〉。已提交的修改不会自动重做 |
| 达到预算上限 | 已达到本轮上限（步骤 / 时间 / 上下文），已提交的修改保留 |

模型是否达成用户目标，由模型在回复正文中自己说明（提示词要求它对照目标逐项说明，见 7.8）；界面不替模型下结论。如果用户要求画图但“产出”一行没有图形，用户一眼就能看出来。

讨论模式没有修改和运行，不显示“本轮结果”，只在署名行写“讨论”。

### 7.5 运行中与停止

- 运行中的回复末尾有一行实时状态：转圈 + “正在运行单元格 8” + “停止”按钮。
- 输入框右下的发送键同时变成停止（黑底方块），⌘. 同效。
- 停止后先显示“正在停止…”，宿主确认后写入第 7.4 节的“已停止”结果。
- 运行中用户可以继续在输入框打字；草稿不会被上一轮的完成清空。

### 7.6 输入框

沿用用户确认的布局（[agent-composer.md](agent-composer.md)），改为本文的视觉：

- 圆角 14 的容器，固定在助手栏底部，不随对话滚动。聚焦时绿色描边加 3 pt 浅绿外圈。
- 第一行（有内容时才出现）：附件卡片（缩略图 40×32、文件名、大小与类型、移除）和单元格引用芯片（“单元格 8 ✕”），可横向滚动。
- 正文：自动增高，最高为助手栏高度的 35%，之后内部滚动（参考 Telegram-iOS 的 adaptive composer `max_fraction 0.35`；TelegramSwift 在 Mac 上是父视图一半加 50，我们取更保守的 35%，给对话留空间）。
- 底部操作行：左 `＋`（文件、图片、引用单元格）→ `执行⌄`；右：上下文圆环 → 模型名⌄ → 发送 / 停止。
- Enter 发送，⇧Enter 换行（设置中可改为 ⌘↩ 发送）。中文输入法合成期间不发送。
- 宿主接受消息后才清空草稿和附件；发送失败保留全部输入。
- 输入框下方一行小字只在需要时出现：“gpt-6-luna 从下一轮开始使用”“讨论模式不会修改或运行笔记本”。

菜单（原生弹出菜单，支持方向键、Enter、Esc，关闭后焦点回到按钮）：

- **模式**：执行（可以修改和运行笔记本，每轮修改都能撤销）；讨论（只读取笔记本，计算在临时环境中进行）。
- **模型**：顶部搜索框；按供应商分组；每项写出能力（工具调用、图片输入）；执行模式下没有工具调用能力的模型置灰并说明“不支持工具调用，切换到讨论模式后可用”；底部“管理模型… ⌘,”。
- **上下文圆环**：弹出框列出“系统与工具说明 / 对话与工具结果 / 本条附件 / 上限及来源 / 上一轮请求的实际用量”；估算值标“预估”；上限未知时圆环为虚线并写“上限未知”。

附件（本版范围）：任意文件都可以加入并保存；图片发送给支持图片的模型；PDF 在 Mac 上用 PDFKit 提取文字后发送；其他格式保留卡片并标注“暂不能发送给模型”，不静默丢弃。

### 7.7 模式与权限

| 模式 | 可用工具 | 不可用 |
|---|---|---|
| 执行 | 全部：读取、查阅、预览、修改、运行、检查、临时计算、核对、撤销 | — |
| 讨论 | 读取、查阅、检查结果、临时计算 | 预览修改、修改、运行、撤销 |

模式取代当前的“允许修改并运行笔记本”复选框。切换模式在下一轮生效。

### 7.8 助手行为：提示词分层

运行时发送给模型的 system 由下列层按顺序拼接（实现见计划 A1–A2）：

1. **身份与边界**（3–5 句）：你在 OpenMath 中操作当前笔记本；数学由内核计算；只调用提供的工具；模式说明（执行或讨论）。
2. **操作指引**：[notebook-operation.md](prompts/notebook-operation.md) 的“模型操作说明”全文（10 条规则）。这份文档是唯一来源，构建时提取进包，Mac 和 Web 共用。
3. **语言卡**：现代语法要点（`let` 赋值、`=` 是等式、`fn(x)=>…`、列表方括号、索引从 1、命名参数 `x: a..b`）、当前版本的已知限制（例如等号后直接换行报 E022）。
4. **已验证示例**：用当前 CLI 实跑过的短源码，包括求解、函数与 map、二维 `plot` 带两条曲线、三维 `scene`（简化的西瓜）。每个示例附实际返回形状。
5. **任务规则**（新增，针对这次的失败）：
   - 画图或计算必须写进**数学单元格**并运行；文字单元格只放说明，不能用 emoji 或文字代替图形。
   - 修改后必须运行受影响的单元格，再用 `inspect_result` 检查；图形任务要确认几何数据存在。
   - 回复结尾对照用户目标逐项说明：做了什么、哪些已验证、哪些没做到以及原因。不能把“回合结束”说成“已完成”。
6. **工具说明**：来自 `agent-tools.schema.json` 的目录描述和参数示例（现有实现已接入，保留）。

模式、模型、日期、版本号作为变量注入。提示词总长控制在约 6k tokens 以内（不含对话），超出时先删示例。

单元格、工具栏、助手统一用这一套词，Mac 和 Web 共用同一组文案键：

## 8. 设置

- **Mac**：系统 Settings 场景（⌘,），工具栏式标签：通用、编辑与计算、模型、助手、数据。
- **模型页**：左侧列表按供应商分组（像“邮件 › 账户”），右侧表单：显示名、API 地址、API Key（钥匙串）、模型列表（每个模型的 API 名称、显示名、能力：工具调用 / 图片输入 / 上下文上限）、“测试连接”。保存失败保留草稿。沿用 [macos-model-media-ux.md](macos-model-media-ux.md) 的数据关系，界面按本文令牌重绘；本版不做多预设和思考强度映射的完整编辑器。
- **助手页**：发送快捷键（Enter / ⌘↩）、默认模式、默认模型。
- **Web**：同样五组，放在一个对话框里（左侧分组导航）。API Key 存在浏览器本地，首次保存时说明存储位置；需要供应商允许 CORS，测试连接失败时直接说明是 CORS 还是认证问题。

### 9.2 动效

沿用 [macos-ux.md](macos-ux.md) 的时长表，补充：

- 左轨“运行中”流动：0.7 s 一周期，线性；减少动态效果时为静态虚线。
- “定位”闪框：靛蓝 4 pt 外圈 1 s 淡出；减少动态效果时只滚动，不闪。
- 操作记录新增一行、本轮结果出现：120 ms 淡入；不做位移动画。
- 手机底部面板：系统 sheet 动画；Web 用 240 ms 位移，减少动态效果时直接出现。

### 9.3 无障碍

- 左轨状态都有文字等价：单元格的读屏标签为“单元格 3，有条件成立，条件 k 不等于 0”。
- 公式提供源码读法和可读标签；图形提供摘要（“二维图，2 条曲线，x 从 −π 到 π”）和缩放、复位、旋转动作。
- 操作记录的每一行是一个列表项，状态用文字读出（“修改笔记本，新增单元格 8，成功”）。流式输出不逐字播报，回合结束时播报“回合结束”和本轮结果的第一行。
- 全部操作可用键盘完成；焦点环为 2 pt 绿色。

## 11. 从 Telegram 学到的做法

用户指定参考 Telegram 的 GitHub。本次实际查阅的源码与采用情况：

| 来源 | 观察 | 采用方式 |
|---|---|---|
| TelegramSwift `packages/TGUIKit/Sources/TextView.swift`（`TextViewBlockQuote`、`isCode`，约 2551–2640 行绘制） | 代码块和引用是同一个块容器：一次画一个圆角矩形（半径 3），左侧 3 pt 竖条，代码块底色用主题色 25% 透明度 | 第 5.6 节：一个容器、一条竖条、整体底色；圆角放大到 6 配合我们的层级 |
| TelegramSwift `Telegram-Mac/ChatMessageItem.swift`（约 865–880 行） | 代码块头部单独排版语言名（中等字重，截断 15 字），正文等宽并做语法高亮 | 头部显示语言名，加“复制”“插入为单元格”；语法高亮本版不做 |
| TelegramSwift `Telegram-Mac/ChatInputView.swift`（`max_height`、`textViewSize`） | 输入框宽度先减去左右按钮再测量文字；最大高度随父视图变化 | 第 7.6 节：先扣按钮宽度再测量；上限取助手栏高度的 35% |
| Telegram-iOS 本地契约 [adaptive-composers](/Users/hert/Documents/ChatGPT/ui-learning/05-input-and-actions/adaptive-composers.md) | 输入法合成期间不发送；发送条件 = 非合成 + 附件就绪 + 有内容；草稿在发送被接受前不清空 | 第 7.6 节全部采用 |
| Telegram-iOS 本地契约 [rich-text-and-entities](/Users/hert/Documents/ChatGPT/ui-learning/08-media-and-rich-content/rich-text-and-entities.md) | 不支持的块结构要明确回退，不能当作已忠实转换 | 无法排版的 Markdown 块显示原文和“无法排版，显示原文” |
| Telegram 的 `PeerNameColors` | 用固定的身份色区分“谁说的” | 靛蓝作为助手的身份色，贯穿署名、操作记录、单元格标记 |
| Telegram-iOS 本地契约 [progress-and-result-feedback](/Users/hert/Documents/ChatGPT/ui-learning/06-state-and-feedback/progress-and-result-feedback.md) | 状态只由真实回执推进，迟到回复按代次丢弃 | 第 5.4、7.4 节 |

没有采用：助手消息气泡（数学内容需要通栏）、聊天列表式侧栏、壁纸、发送时的形变动画。只读源码和本地 Markdown 契约，不复制 Telegram 的类体系或资源。

## 12. 设计验收（每个里程碑都做）

这一节是这次失败的直接补救：**每完成一个界面里程碑，都要和草案逐项对照**，写进进度记录。

做法：把实际应用和草案在相同尺寸、相同主题下截图并排比较。Mac 在 1440×900 浅色和深色、1000 宽、800 宽下截图；Web 在 1440、1000、390 宽下截图。逐项回答“是/否”，“否”要写原因和处理办法。

检查表：

1. 三栏宽度、断点和收起行为与第 5.1 节一致。
2. 工具栏只有第 5.1 节列出的项目；没有底部状态栏。
3. 数学单元格是“源码槽 + 纸面结果 + 左轨”，没有卡片和阴影。
4. 左轨 7 种状态（第 5.2 节）都能实际出现，并且有文字状态。
5. 解集一行显示；条件以芯片显示；>4 个解用表格。
6. 过期结果半透明并写明原因，有“运行以更新”。
7. 文字单元格默认阅读态，衬线正文，双击进入编辑。
8. 代码块是单个容器，横向滚动，有语言名和复制。
9. 二维图例在下方，控制在右上悬停出现；三维图可拖动旋转。
10. 检查器有助手、步骤、变量三个分段，各自保留状态。
11. 助手回复有署名行（模型、模式）。
12. 每条回复有自己的操作记录；失败操作可见；有定位、查看差异、撤销。
13. 执行模式回合结束有“本轮结果”，内容来自宿主事实；没有“已完成”字样。
14. 输入框：附件行、引用芯片、自动增高至 35%、执行/讨论、上下文圆环、模型菜单、发送/停止。
15. 模型菜单在执行模式下禁用无工具模型并说明原因。
16. 中文输入法合成时按 Enter 不发送。
17. 运行中可停止，停止结果如实显示。
18. 深色模式所有令牌对比度达标，三维画布跟随主题。
19. 手机 Web 单栏，“助手”按钮打开底部面板。
20. 减少动态效果开启时，所有动画变为静态，功能不变。
