# Implementation rulings

The approved product scope is unchanged. Entries below resolve engineering conflicts in PLAN.md.

## 2026-09-30 — foundational preflight

- **P1 — cancellation types:** M2.8 produces `Interrupt/Clock/Abort`, consumed by M5–M9. Define these expression-independent types in `om-num::ctx` and re-export from `om-core::ctx`; messages remain in om-core. This preserves om-poly's no-om-core dependency rule and every consumer's concrete type. Cost if wrong: moving a small module, without changing signatures.
- **P2 — Rust/reedline:** keep Rust 1.94.0, pin reedline to `=0.49.0`. The registry records Rust 1.95.0 for reedline 0.50–0.52 and 1.63.0 for 0.49.0. Cost if wrong: update CLI adapters when a newer toolchain is adopted.
- **P3 — progress hashes:** mark a task complete with verification commands in its commit; add that commit's hash in the next task commit. A commit cannot contain its own final hash. The ignored execution ledger records hashes immediately after committing.
- **P4 — contract names:** use `Abort::Interrupted` and `Verification`; fix obsolete milestone references and the plan header's section numbers. `recip(0.)` returns `NumError::DivByZero`, not an IEEE infinity, preserving the numeric layer's finite-value policy.
- **P5 — tool setup:** install cargo-deny now; defer wasm-bindgen-cli and cargo-insta until their first consumer. The WASM target is already installed. Avoid large unused tool builds and pin wasm-bindgen-cli to the eventual locked crate version. Cost if wrong: a deferred one-time tool installation.
- **P6 — bootstrap CI:** M0.1 validates WASM with om-num, the only crate that exists; switch to om-kernel in M0.2. Reserve frontend/type-generation checks for their introducing tasks so CI never invokes nonexistent packages.
- **P7 — license policy:** MPL is not globally allowed; any required MPL-only transitive package needs a named exception. This enforces the plan's transitive-only allowance rather than permitting new direct MPL dependencies.
- **P8 — task tooling:** existing task-start extracts `Task N` headings, not this plan's `M<n>.<n>` checkboxes. Generate per-task briefs directly from the authoritative plan, retaining BASE and task-done test logs. Cost if wrong: only execution tooling, not application behavior.
- **P9 — execution:** the user prohibited further workflows/subagents. Implement and perform separate review passes inline, with fmt/clippy/test gates. No automatic merge/publication; the user authorized pushing verified commits to `https://github.com/He-RT/om-openmath.git` on 2026-09-30.

- **P10 — scaffold API:** omit meaningless `placeholder()` exports and tests. Cargo package-graph boundary tests and actual native/WASM builds verify scaffolding without creating fake runtime functionality. Source modules are otherwise empty until their implementation task.
- **P11 — dependencies:** reserve approved external versions in workspace.dependencies and activate each dependency at its first consumer. `ctrlc` is included because §12.12 already requires it, despite its omission from the main whitelist. HTTP and native config feature slots exist now; their transports are introduced and tested in M11/M12.

- **P12 — frontend runtime:** preserve Vitest 5/jsdom 30 and pin Node 26.0.0 in app/.nvmrc and CI. Their declared engines exclude the installed Node 25.9. Local verification uses an ignored project-local Node binary; the global runtime is unchanged. Cost if wrong: update the runtime pin.
- **P13 — TypeScript/linter compatibility:** typescript-eslint 8.70.1 declares TypeScript >=4.8.4 <6.1.0. Use TypeScript 6.0 rather than the incompatible planned 7.0; do not use --force or --legacy-peer-deps. Cost if wrong: a compiler upgrade once lint tooling supports it.

- **P14 — desktop scaffold:** compile a real Tauri/Wry window in M0.3, not a headless facade. File/dialog/opener plugins and their permissions remain deferred to M13, when their consumers and tests exist. Cost if wrong: native build prerequisites, rather than a silently nonfunctional desktop app.

- **P15 — desktop dependency policy:** allow MPL-2.0 only for the five exact-version, unmodified Tauri transitives named in `deny.toml`/`THIRD_PARTY_NOTICES.md`. Except only RUSTSEC-2024-0370 (unmaintained proc-macro-error in Linux GTK build macros, no safe upstream upgrade); do not suppress vulnerability advisories or broaden license policy. Cost if wrong: revisit the desktop dependency chain before release.

## Deferred contract checks (resolve before first consumer)

- **P16 — Number invariants (M1.1):** §8.1.0's explicit rule wins over §6.1's abbreviated `im != 0` comment: retain approximate zero imaginary parts. Complex normalization flattens nested components and propagates precision to both; if a component cannot fit binary64, both use 53-bit Big. Direct construction of Real assumes finite values; arithmetic enforces that precondition. Big serialization uses explicit binary significand/exponent/precision so JSON retains values and bit precision independently of decimal formatting. `to_complex_f64` is a lossy export boundary: out-of-range components become signed infinity, while `to_f64` returns None and Number arithmetic remains finite.
- **P17 — exact integer-power resource limit (M1.1):** add `NumError::ExactOverflow` for the §8.1.4 `2^24`-bit exact-result limit. Check growth during exponentiation, including arbitrary-size exponents, so the primitive cannot allocate without bound before M2.6 handles the error symbolically. Unit bases remain valid for arbitrarily large exponents. No existing signature changes.
- **P18 — numeric task dependency (M1.2):** introduce `SplitMix64` in M1.2, its first required consumer (Pollard-Brent), with known-vector and range tests. M1.3 remains open for Fp/Ball. Number-theory boundary conventions: gcd is nonnegative; zero factors as `(0,1)`, negatives include `(-1,1)`, units otherwise have no factors; perfect_power returns None for 0/±1 (there is no maximal exponent). exact_root returns None for k=0; isqrt requires n>=0. extract_root_factor requires k>0 and rejects negative even radicands, and does bounded prime trial extraction through 2^16 plus an exact remaining kth-power check; an unresolved large composite can retain kth-power factors, as §8.1.4 explicitly forbids full factorization in constructors. Factorization budget charges trial remainders and rho polynomial evaluations; exhausted cofactors stay explicit and reconstruct the original integer.
- **P19 — finite-field methods (M1.3):** preserve `Fp { pub p: u64 }`; add `new(p)->Option<Fp>` to validate primality, `add/sub/mul(a,b)->u64`, `pow(a,e)->u64`, and `inv(a)->Option<u64>`. Residues are normalized and u128 intermediates avoid machine overflow. Direct construction requires p>=2 and, for field semantics, prime p; inversion returns None for nonunits.
- **P20 — rigorous balls (M1.3/M1.4):** retain Ball/CBall fields and all prescribed method signatures. Use Dashu's directed Down/Up endpoints for exact conversion and arithmetic, derive a HalfEven midpoint, then round the radius upward (at min(prec,64) bits). This encloses input uncertainty, operation rounding and recentering without a guessed universal one-ulp bound. `mid=0, rad=+inf` represents the whole real line and must be handled before arithmetic with infinities. sqrt of a ball including negative values returns whole; div with a zero-containing denominator returns whole. Add `Ball::whole(prec)` and `CBall::exact(re,im,prec)` plus CBall's basic add/sub/mul/div/pow_int as shared construction helpers. Dashu 0.6.1 now also exposes trigonometric methods, but exp/ln/pi/sin/cos/atan and complex elementary functions stay in M1.4 with explicit interval/domain and error proofs; M1.3 only claims arithmetic and sqrt.
- **P21 — elementary balls (M1.4):** exp/ln use Dashu 0.6.1's Ziv-certified directed endpoint evaluations (local exp.rs/log.rs), which already include Taylor/reduction error. Implement atan/sin/cos/Machin pi locally using reduced Taylor series with explicit first-omitted-term bounds and outward ball arithmetic. Cache complete certified pi balls, rather than only the planned BigFloat midpoint; otherwise the certificate would be lost on cache hits. Sin/cos propagate input radius with their global 1-Lipschitz bound and return [-1,1] for whole inputs; ln of a nonpositive-containing real ball returns whole. Complex ln uses principal argument (-pi,pi], returning the full argument interval when crossing the negative-axis cut; origin-containing logarithms return whole components. Complex sqrt has nonnegative real part and uses +imaginary values on the negative real axis; input uncertainty across the cut is enclosed rather than assigned an arbitrary sign. No public signatures change.
- **P22 — symbol persistence (M2.1):** fixed built-in IDs remain in §6.2's exact order. Dynamic IDs are process-local and may depend on concurrent interning order, so Symbol's added Serialize/Deserialize traits persist names and intern them on read. The global table is initialized with every built-in before accepting user names and uses FxHashMap with deterministic hashing; Ord remains ID order for containers only. No function signatures change.

- **P23 — expression structure (M2.2):** expression equality preserves numeric variants and Big bit precision (even when Dashu numeric equality ignores context); signed machine zeros compare and hash equally. Expr stores only finite normalized Number values. Traversals include explicit compound heads, but free_symbols reports symbols in argument positions, excluding built-in constants; user function names used as heads are not inferred solve variables. leaf_count counts atomic leaves including compound heads. Structural replacement is simultaneous, chooses the first matching rule and does not revisit replacement values. As §13 M2.2 explicitly permits, replace_all/map_args initially rebuild raw trees; M2.7 will connect canonical constructors. Public signatures remain unchanged.

- **P24 — total ordering (M2.3):** apply §8.1.1’s explicit `(lowercase name, original name)` tuple. The specification leaves numeric bases of powers, equal-bit Machine/Big variants, signed Big zeros and raw degenerate forms such as x vs Power[x,1] unspecified. Numeric bases sort before other atom kinds; after prescribed value/precision keys, use numeric representation and structural kind/head/argument keys for deterministic ties. This makes Equal equivalent to Expr structural equality without using interner IDs or cached hashes. Existing canonical-form order is unchanged.

- **P25 — constructor task dependencies (M2.4–M2.7):** implement each public constructor in its scheduled task. M2.4’s coefficient rebuild uses a private minimal Times assembly until M2.5 connects mul; pow-driven roots and -1 distribution remain in M2.5/M2.6. The milestone lists assign mixed expressions (e.g. 0*x, sqrt, infinity products and E^Log[x]) to earlier tasks than their required constructors; track those vectors explicitly as deferred and require all 40 in M2.6/M2.7, rather than claiming placeholder behavior passed. Plus accepts Infinity as DirectedInfinity[1] and the documented [ComplexInfinity alias](https://reference.wolfram.com/language/ref/ComplexInfinity.html) as DirectedInfinity[]; any additional infinity beside an undirected infinity is Indeterminate (including another undirected one), interpreting §8.1.2’s “other infinity” literally. No signatures change.

- **P26 — product staging and infinities (M2.5):** introduce a private integer/perfect-rational-root Power rebuild at mul’s first consumer; M2.6 replaces it with the full public pow constructor. M2.5 validates its own multiplication vectors and records single-Power root extraction/Euler identities as pending M2.6. Zero of either exact or approximate category times an infinity is Indeterminate: the phase w/|w| is undefined at every literal zero. Directed infinity multiplication retains unknown finite symbolic factors; only numeric coefficients and directions are combined into a unit phase. Undirected infinity absorbs nonzero factors. No signatures change.

- **P27 — Power precision and diagnostics (M2.6):** symbolic identity rules use exact 0/1; approximate numeric arguments are evaluated with contagion instead of losing their category (2^1.0 becomes 2.). Nonzero purely imaginary exponents at literal zero are Indeterminate. Introduce §6.4 Message/MsgLevel/Messages at their first consumer, plus `with_canonical_messages<T>(f: impl FnOnce()->T)->(T,Vec<Message>)`: a scoped, thread-local, panic-safe capture of constructor diagnostics, usable in a single-thread WASM worker. pow keeps its specified signature and emits Power::infy/General::ovfl into an active capture; M4/kernel will attach the captured messages to evaluation. No process-wide pending queue or numerical infinity is created. Approximate powers use guarded Ball/CBall principal log/exp at target precision plus guard bits, then round once; unrepresentable Dashu exponents remain symbolic with ovfl. Debug FullForm spells internal DirectedInfinity[] as ComplexInfinity to honor §8.1.5.

- **P28 — rational roots (M2.6):** when numerator and denominator share a reducible perfect-power degree, reduce them together; otherwise split only the reducible side(s), preserving positive-base branch safety. Root degrees larger than u32 keep a symbolic reduced fraction after the integer part is extracted, rather than truncating the degree. Resource-limit rejection keeps the original Power. Constructors do not perform complete factorization, as required by §8.1.4.

- **P29 — numeric trait boundary (M2.6):** re-export Dashu’s `BitTest` from om-num for exact-result size checks and future polynomial consumers. om-core imports the trait through om-num, preserving the requirement that other crates do not directly depend on Dashu. No Number or constructor signature changes.

- **P30 — stable infinity phases (M2.6):** recognize exact unit phases of the form Complex[a,b]·(a²+b²)^(-1/2), and normalize each infinity direction and the numeric coefficient before multiplying phases. Preserve Sign[z] wrappers under repeated normalization; an approximate complex coefficient is represented as Sign[coefficient] until numeric Sign evaluation, preventing rounding cycles from changing a direction across canonicalization passes. Positive real scaling leaves an established direction unchanged. This is a structural stability rule, with exact-complex idempotence regressions. No public signatures change.

- **P31 — public canonical traversal (M2.7):** canonicalize visits every explicit head and argument in iterative postorder, including Hold syntax; evaluator holding is handled before recursive canonicalization of held input in M4. replace_all first performs simultaneous structural replacement on the original tree, then canonicalizes once; map_args canonicalizes the rebuilt compound tree. func dispatches arithmetic/Sqrt/Exp/infinity structure only; Sin/Log and other exact special values remain in om-simplify as §4 requires. [DirectedInfinity documentation](https://reference.wolfram.com/language/ref/DirectedInfinity.html) specifies that an Indeterminate direction is undirected and nested infinities collapse. Treat literal zero direction as undetermined as well (an explicit inference from the undefined phase), while zero multiplied by any infinity remains Indeterminate. Arithmetic constructors also resolve literal I/Infinity/ComplexInfinity aliases on entry, so direct calls and whole-tree traversal agree. All listed public signatures are retained.

- **P32 — interrupt polling (M2.8):** preserve all §6.4 fields. Add Default with 500,000,000 allowed ticks; N ticks succeed and the next returns Budget, without underflow. Check the atomic cancellation flag on every tick for immediate Ctrl-C response. Poll an injected clock every 4096 remaining steps, also at the initial default budget and throughout the final 4096-step window; the latter makes small custom budgets and already-expired deadlines responsive without adding hidden state. Error priority is Interrupted, then exhausted Budget, then Timeout. Missing clock disables deadline checks. No native time dependency is introduced into the libraries. Abort additionally derives PartialEq/Eq for typed validation. Message types/capture were already implemented at their M2.6 first consumer and are re-exported from om-core::ctx.

- **P33 — shared lexer (M3.1):** introduce §6.5 Dialect/Span/Diagnostic/Fix/Severity/TokenClass at their first consumer, preserving prescribed fields and UTF-8 byte offsets. Add `lexer::{lex(src: &str, dialect: Dialect) -> LexOutput, LexOutput, Token, TokenKind}`; token payloads remain in the source via spans, so numbers keep spelling/precision and adjacent calls can be distinguished from multiplication. Retain comments and newlines for highlighting and statement boundaries; skip other whitespace. Modern `#` starts a line comment and underscores are identifier characters; Wolfram `#`/`#1` are slots and underscores are blank operators. Emit square brackets individually to preserve nested modern lists and Wolfram calls/Part. Numeric conversion and automatic dialect detection remain in M3.2/M3.3 (`lex` with Auto uses Modern). Lexical errors use E001–E006 and recover to a token boundary; inputs exceeding u32 byte spans produce E007. No extra dependency is required.

- **P34 — modern parser (M3.2):** preserve §6.5 parse/parse_expr/detect_dialect and output fields. Supply the referenced but unspecified `ParseEnv { known_functions: BTreeSet<Symbol>, constants: ConstantMode }`, `ConstantMode::{Math,Strict}`, and `parse_with(src, dialect, &ParseEnv)` with mathematical constants by default. Function declarations extend the known-function set within the cell; their parameters shadow constant aliases. Function aliases apply at calls, preserving free lowercase c/d/n. Add `om_core::builtins::names()` to use the authoritative symbol table without duplicating it. Exact canonical `Root(...)` retains Root objects, while the modern `root(...)` alias builds Power. Parsing creates raw expression trees, including division as Times/Power and function parameters as Pattern/Blank, without invoking canonical constructors. `steps:` becomes Rule[RecordSteps,value] for the future Solve/kernel consumer; `domain: positives` adds strict positivity conditions for explicit variables and selects Reals. Add the approved om-num dependency for literal conversion. Decimal conversion rounds an exact rational once to binary precision; nonzero machine underflow/overflow uses a 53-bit Big. Reject excessive literal sizes/exponents/precision with E011 and excessive syntax nesting with E013 instead of panicking. Detection ignores quoted text and line comments, preserves original offsets across first-line dialect markers, and counts distinct Wolfram indicators. Wolfram parsing remains pending M3.3 and reports E020 until then.

- **P35 — Wolfram parser (M3.3):** implement the supported subset in the relative ordering and associativity of the official [Operator Input Forms](https://reference.wolfram.com/language/tutorial/OperatorInputForms.html). Square-bracket calls accept arbitrary heads and whitespace; parentheses always group/multiply. Keep literal symbol case and native Pattern/Blank, Slot, Function, Derivative, Set/Unset, Apply/Map and replacement heads. Homogeneous comparison chains retain n-ary heads (in particular, Unequal means pairwise distinct); mixed ordering chains use Inequality, leaving evaluation/normalization to M4. Newlines separate top-level statements; semicolons inside a Wolfram expression build CompoundExpression, including trailing Null and output suppression. Precision markers specify ceil(decimal_digits·log2(10)) binary bits; share M3.2's finite literal conversion and resource limits. Follow the official [Input Syntax](https://reference.wolfram.com/language/tutorial/InputSyntax.html) threshold of at most 17 significant decimal digits for unmarked machine literals (Modern retains its prescribed 16); a bare backtick forces machine rounding directly from decimal to avoid double rounding. Modern e/0x spellings remain symbol multiplication in Wolfram, which uses *^/base^^ instead. Named Greek letters expand within identifiers and strings; standalone Pi/Infinity characters become the corresponding constants. No public signatures change and no new dependency is needed. Modern ** remains exponentiation; the unlisted Wolfram ** operator is rejected rather than misparsed as Power.

- M4.4/M4.5 use exact special values and numeric expression evaluation assigned to M8. Implement the shared special/numeval modules before their first evaluator consumer; do not add an upward dependency.
- Elementary domains and rounding are settled in P20/P21; implementation evidence is tracked in PROGRESS.md.
- Ring static zero/one cannot select a runtime finite-field modulus; settle coefficient-context construction in M5.1.
- Kernel view/envelope/span and LLM transport ownership gaps will be resolved and fixture-tested before M11/M12, retaining the public fields where possible.

No preflight agent returned a completed report; neither math nor protocol correctness has been certified by those failed runs.

## Parser diagnostic repairs

- **P36 — diagnostics and Fix (M3.4):** keep the prescribed optional Fix fields. W001 spans only the separating whitespace, W002 the unknown function identifier, and E010 the complete missing-parenthesis application. Add E023 for unclosed grouping delimiters (point at the innermost opener and insert all outstanding closers) and E024 for unexpected/mismatched closers (delete or replace the exact token). Inspect lexical bracket tokens, ignoring comments and strings, and suppress duplicate generic parser errors at the same delimiter. Append a newline before closers when the source ends in a line comment. Unterminated string/comment diagnostics also offer insertion repairs, retaining original text. Optional Fix remains absent when the intended replacement is ambiguous or an error is a resource limit; no arbitrary source deletion is proposed for unknown characters or malformed numbers.

## Source formatter contract

- **P37 — source forms and precision (M3.5):** §7.1 requires raw parser trees, so source-form round trips compare `canonicalize(parse_expr(form, dialect))` with the canonical input Expr; this preserves the same normal form and numeric category without changing parsing to evaluate arithmetic. FullForm reuses core's documented Debug spelling (including binary bit precision for Big). Source forms use Wolfram decimal-digit precision markers, with a fractional marker whose ceiling maps exactly to the original bit count. Permit the already-lexed backtick precision marker in Modern as an additive literal spelling, using the same converter; a bare marker forces Machine. This is needed because Modern's automatic decimal-digit precision cannot represent all bit counts or every binary64 mantissa. Strings use JSON-compatible escapes. Display sorting is private and does not reorder the internal tree. Generic explicit calls retain supported heads. Add adjacent call chaining after explicit Modern calls (`f(x)(y)`), including `Derivative(1)(f)(x)` and `Plus(a,b)(x)`; grouped arithmetic `(a+b)(x)` remains multiplication. Preserve exact native `Derivative` ahead of the lowercase `derivative` alias to D. Arbitrary atomic non-symbol heads and literal symbol aliases remain subject to the source grammar and selected constant mode. Keep the prescribed signatures and add `input_form_with(e: &Expr, options: &FormatOptions) -> String` / `modern_form_with(e: &Expr, options: &FormatOptions) -> String` to consume display_order; om-num and test-only om-parse/proptest are approved dependencies.

- **P38 — mathematical display (M3.6):** keep latex/unicode_form signatures, reuse source-printer term degree and sign handling, and render independently of parseable source spelling. Display preserves branch-sensitive Power trees; square/cube roots and inverse powers use roots/fractions without algebraic simplification. Escape arbitrary symbols and strings before placing them in KaTeX text commands. Unknown functions use operator names and arbitrary compound heads remain visible. Unicode is a display form (typographic minus/superscripts/roots), not a persistence format; InputForm/Modern remain the round-trip boundary. KaTeX validation uses an isolated ignored local install of the approved 0.18 renderer, with no frontend dependency activation or network in tests.

## Evaluator staging

- **P39 — evaluator foundation (M4.1):** implement the §9.1 named interfaces at their first consumer: Definitions/Rule, Attributes/Arity/BuiltinSpec/DocEntry/BuiltinTable, EvalSettings (Clone/serde; defaults 4096/1024/true), EvalError and Evaluator. Add a private readonly flag for fork_readonly. Assignment/control builtins are functional now, with their holding attributes and arity; general Hold/Listable/Sequence remain M4.2, pattern matching M4.3, and the full arithmetic/doc registry M4.4. Literal downvalues use structural equality, while pattern downvalues are stored until M4.3. An initial recursive implementation overflowed the native stack before the default 1024 logical-depth limit. Use heap frames for head/argument evaluation, own-value chains, compound sequencing and tail rewrites, with explicit logical depth and an iteration counter; restore depth on every Result path. Capture constructor messages only at rebuild. The last_steps field is introduced with the real Steps type in M9.1, before Solve is connected in M10.2; do not invent a placeholder Steps representation or bring all its algebraic dependencies into M4.1. Existing field and method names are retained as they are introduced. Readonly forks copy definitions/settings/history, start with fresh messages, and reject all definition mutations. Protected built-in names cannot be assigned or cleared.
