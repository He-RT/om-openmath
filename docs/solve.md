# Equation solving

The solver is specified in [PLAN.md §8](plan/PLAN.md#8-算法规格) and the acceptance corpus in §14. No Solve implementation is available yet. Supported methods and compatibility differences will be documented here as verified solver tasks land.

P0/P1 preparation is implemented as `om_solve::normalize::normalize`. It preserves original denominator/function exclusions and raw residuals, separates logical branches, infers variable domains and prepares uncanceled polynomial numerators. The public Solve algorithms and frontend integration remain in subsequent M9/M10 tasks.

When variables are inferred and there are more variables than equality constraints, OpenMath emits `Solve::svars` and solves for the first n variables in name order; remaining symbols are parameters (PLAN §7.5). Constraint-only input retains its inferred variables. Explicit variable lists preserve their requested order. These are OpenMath compatibility choices. Multivariate inequalities and logical expansion beyond 64 branches are marked unsupported rather than reported as an empty solution.

Chained `Unequal[a,b,c]` produces all pairwise nonzero restrictions; `Element[{x,y}, Reals]` and `Element[x|y, Reals]` apply the domain to each variable. These follow the official [Unequal](https://reference.wolfram.com/language/ref/Unequal.html) and [Element](https://reference.wolfram.com/language/ref/Element.html) documentation.

The M9.3 candidate kernel `om_solve::univariate::poly_uni` now solves exact rational polynomials whose complete factorization contains only linear and quadratic factors. It clears rational denominators, uses Yun and certified integer factorization, composes root multiplicities, and orders rational-coefficient roots by certified real/imaginary algebraic comparisons. It also extracts independent coefficient content and zero-root powers for parameter polynomials before applying linear/quadratic formulas. All candidates carry construction provenance; original restrictions and requested-domain filtering are later dispatcher stages.

Parameter roots retain generic nonzero-leading and coefficient-denominator assumptions. The default keeps these in computation metadata; `MaxExtra::All` exposes them through `ConditionalExpression`, and `Count(n)` attaches a complete conjunction only when it fits. Wolfram-shaped output repeats each root according to its multiplicity, as specified for OpenMath. A currently unsupported factor makes the whole candidate set unevaluated. General Root/Cardano/Ferrari paths and domain filters remain subsequent M9 work; this does not yet expose a user-facing Solve builtin.

M9.4 adds `a*x^n+b` radicals, maximal `p(x^k)` substitution, and even palindromic polynomials via `z=x+1/x`. Every inverse branch is retained and its multiplicity is multiplied by that of the reduced root. The reduced equation must be fully supported; otherwise the complete candidate result remains unevaluated. Auxiliary symbols avoid existing coefficients and compound expression heads. Symbolic coefficient content and zero-root powers can be combined with these reductions.

For Q factors above degree two, formula roots are matched uniquely to certified algebraic roots of the original factor. Real-first ordering uses disjoint directed enclosures for strict comparisons and exact conjugate/projection identities for overlapping components. Algebraic certification currently inherits the degree-64 and 16,352-bit limits of om-poly; an unresolved association or projection returns `Unsupported` rather than guessed ordering or partial roots. Parameter results use canonical symbolic ordering. Root objects and general cubic/quartic formulas are the next task.

The checked `om_poly::algebraic_roots` batch constructor shares the original root-numbering contract with `algebraic_root`, returning all distinct certified values from one factorization and isolation. This solver uses that batch and reuses the certified complex disks. Six release candidate-kernel probes spanning cubic/quintic binomials, nested substitutions and mixed quartics take 15–109 ms on the development Mac; these timings do not yet cover the future complete Solve dispatcher.
