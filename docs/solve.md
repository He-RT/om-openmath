# Equation solving

The solver is specified in [PLAN.md §8](plan/PLAN.md#8-算法规格) and the acceptance corpus in §14. Polynomial candidate kernels are implemented; the user-facing Solve builtin and complete dispatcher are subsequent M9/M10 tasks.

P0/P1 preparation is implemented as `om_solve::normalize::normalize`. It preserves original denominator/function exclusions and raw residuals, separates logical branches, infers variable domains and prepares uncanceled polynomial numerators. The public Solve algorithms and frontend integration remain in subsequent M9/M10 tasks.

When variables are inferred and there are more variables than equality constraints, OpenMath emits `Solve::svars` and solves for the first n variables in name order; remaining symbols are parameters (PLAN §7.5). Constraint-only input retains its inferred variables. Explicit variable lists preserve their requested order. These are OpenMath compatibility choices. Multivariate inequalities and logical expansion beyond 64 branches are marked unsupported rather than reported as an empty solution.

Chained `Unequal[a,b,c]` produces all pairwise nonzero restrictions; `Element[{x,y}, Reals]` and `Element[x|y, Reals]` apply the domain to each variable. These follow the official [Unequal](https://reference.wolfram.com/language/ref/Unequal.html) and [Element](https://reference.wolfram.com/language/ref/Element.html) documentation.

The M9.3 candidate kernel `om_solve::univariate::poly_uni` solves exact rational polynomials whose complete factorization contains only linear and quadratic factors. It clears rational denominators, uses Yun and certified integer factorization, composes root multiplicities, and orders rational-coefficient roots by certified real/imaginary algebraic comparisons. It also extracts independent coefficient content and zero-root powers for parameter polynomials before applying linear/quadratic formulas. Later tasks extend the same kernel below. All candidates carry construction provenance; original restrictions and complete verification remain dispatcher stages.

Parameter roots retain generic nonzero-leading and coefficient-denominator assumptions. The default keeps these in computation metadata; `MaxExtra::All` exposes them through `ConditionalExpression`, and `Count(n)` attaches a complete conjunction only when it fits. Wolfram-shaped output repeats each root according to its multiplicity, as specified for OpenMath. An unsupported component makes the whole candidate set unevaluated. Integer/rational domain filters remain subsequent M9 work; this does not yet expose a user-facing Solve builtin.

M9.4 adds `a*x^n+b` radicals, maximal `p(x^k)` substitution, and even palindromic polynomials via `z=x+1/x`. Every inverse branch is retained and its multiplicity is multiplied by that of the reduced root. The reduced equation must have wholly radical roots; since M9.5, a reduction that only yields Root objects falls back to Root objects of the original factor. Auxiliary symbols avoid existing coefficients and compound expression heads. Symbolic coefficient content and zero-root powers can be combined with these reductions.

For Q factors above degree two, formula roots are matched uniquely to certified algebraic roots of the original factor. Real-first ordering uses disjoint directed enclosures for strict comparisons and exact conjugate/projection identities for overlapping components. Algebraic certification currently inherits the degree-64 and 16,352-bit limits of om-poly. M9.5 falls back atomically to the original factor's Root objects when radical association fails; unavailable certification or ordering returns `Unsupported`. Native Root function/polynomial/index identity uses the certified batch directly. Parameter results use canonical symbolic ordering.

The checked `om_poly::algebraic_roots` batch constructor shares the original root-numbering contract with `algebraic_root`, returning all distinct certified values from one factorization and isolation. This solver uses that batch and reuses the certified complex disks. Six release candidate-kernel probes spanning cubic/quintic binomials, nested substitutions and mixed quartics take 15–109 ms on the development Mac; these timings do not yet cover the future complete Solve dispatcher.

M9.5 supplies general `Root[Function[polynomial(Slot[1])], k]` candidates with one-based indices after factorization and special reductions. `Cubics -> False` and `Quartics -> False` remain the defaults for general factors. Enabling them uses depressed Cardano and Ferrari formulas; Ferrari independently enables Cardano for its resolvent, chooses a certified positive real resolvent root, and uses a biquadratic reduction when the depressed linear coefficient is zero. Generic parameter coefficients keep symbolic Root objects and their leading assumptions. Multiplicities still come from Yun and complete integer factorization.

Formula-derived realness is remembered only after certified root association. Ball evaluation retains the formula's computed real component and intersects with the proven real axis, including rational combinations of flattened sums. Missing certificates use bounded algebraic proof with recursion protection; failed proof can decline numeric evaluation. Tiny imaginary intervals alone never certify realness. Recorded steps contain the actual substitutions, discriminants, eliminant, factors and formula results; `record_steps=false` suppresses all recording even with an enabled sink.

M9.6 honors `SolveOptions::domain = Reals` at the polynomial candidate boundary. Distinct real-root counts come from exact isolation of the Yun square-free parts, preserving multiplicities in repeated inputs. A native rational Root is real exactly when its index does not exceed its defining factor's real count; that count is shared across the factor's Root objects. Radical candidates use directed imaginary enclosures at 64, 256, 1024 and 4096 bits. An interval excluding zero proves nonreal, an exact zero imaginary ball proves real, and exactly the certified number of remaining Q roots proves them real by completeness. A small radius or zero midpoint alone is insufficient.

Unresolved realness is retained with `Solve::real` diagnostics in `PolynomialRoots::messages` and actual Note steps. DomainFilter records retained/rejected distinct candidate counts and before/after values. Disabling steps preserves diagnostics. Parameter assumptions and root expressions stay attached to retained solutions; numeric refinement can reject tiny nonzero imaginary perturbations without claiming realness for an unresolved interval.
